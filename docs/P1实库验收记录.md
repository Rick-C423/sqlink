## 本轮发现与修复

1. **SQLite REPLACE/IGNORE 约束可能隐式影响未选中的行。** 受控 INSERT/UPDATE 固定使用 `OR ABORT`，失败整组回滚；增加真实 SQLite 插入、更新和 DEFAULT VALUES 反例。
2. **SQLite affinity 的匹配顺序必须与数据库一致。** 按 INT → CHAR/CLOB/TEXT → BLOB/空声明 → REAL/FLOA/DOUB → NUMERIC 处理；`TEXTINT`、`VARCHARINT`、`FLOATING POINT` 不再按文本/浮点误判。真实回读和纯函数反例通过。
3. **提交结果未知后不能换 ID 重发旧快照。** 注册表原子认领 `(resultId,revision)`；运行中/unknown/committed 都阻止换 ID 重放。unknown/committed 消费原上下文；确认未提交或确认回滚才释放认领。故障注入和回执详情过期反例通过。
4. **MySQL 授权目录不能单独证明持有会话的触发器可见性。** 两次隔离探针证实：旧会话新增全局 TRIGGER 后，目录计数为 1，但真实触发器仍不可见；精确 schema 授权也需下一次 USE 才生效。实现仅接受表/精确 schema 直接授权，核验后 USE，再读触发器目录。永久实库回归通过。
5. **MySQL 约束检查关闭时拒写。** 同租约检查 `foreign_key_checks=1` 和 `unique_checks=1`；关闭时拒绝，归还后后续租约恢复 `1/1`，原行不变。
6. **修正取消测试夹具。** MySQL 对 `SLEEP()` 投影被中断可返回成功值 1，不能将它当作 1317 取消错误的断言依据。改用真实表查询的 WHERE 谓词；8.4 与 5.7 的取消、隔离和复用均实际通过。没有把“已发送取消”伪装成“执行已取消”。行为依据见 [MySQL 官方函数文档](https://dev.mysql.com/doc/refman/8.0/en/miscellaneous-functions.html#function_sleep)。

## 当前逐类型开放范围

| 数据库 | 可进入受控编辑的首批类型 | 其他必要条件 |
| --- | --- | --- |
| SQLite | INTEGER affinity、TEXT affinity、BLOB affinity、REAL affinity | main 基础表、完整可信主键/原值、无不支持触发器、外键及其他 PRAGMA 满足安全条件 |
| PostgreSQL 17 | bigint、varchar/character varying、text、bytea | 普通持久基础表，排除 RLS、规则、触发器、继承等未验证语义 |
| MySQL 8.4 | signed bigint、varchar、varbinary | InnoDB、目录身份/直接触发器可见性可证明、严格模式、兼容 utf8mb4、外键/唯一检查开启 |

必须由后端发布 `allowedOperations`、`columnInputKinds` 和列 `writable`。生成/标识列不可直接修改；只要表中有未验收字段类型，整表保守只读。普通 SQL、筛选、视图、缺主键、未知来源仍只读。小数、时间、更多整数/文本类型及其他版本需要各自实库证据后扩展，不能由前端显示值推断。
