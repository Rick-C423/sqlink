# SQLink 构建与发布操作手册

> 本文档只描述可重复执行的构建、打包和发布操作。项目背景、架构和风险见[《项目交接文档》](项目交接文档.md)；IPC 和 MCP 接入分别见[《对接文档》](对接文档.md)和[《MCP 工具》](MCP工具.md)。

## 1. 构建模式怎么选

| 使用场景 | 推荐命令 | 结果 |
| --- | --- | --- |
| 日常开发，边改边看 | `npm run tauri dev` | 启动开发窗口，支持前端热更新，不生成交付文件 |
| 调试交付，只要一个最新 EXE | `npm run tauri build -- --no-bundle` | 生成 Release EXE，不生成 MSI/安装器 |
| 正式 Windows 发布 | `npm run tauri build` | 生成 Release EXE、MSI 和 NSIS 安装包 |
| 只检查前端能否构建 | `npm run build` | 生成 `dist/`，不编译 Rust |
| 只验证 Rust | `cargo test --manifest-path src-tauri/Cargo.toml` | 编译并运行 Rust 测试，不生成安装包 |

### 1.1 “调试时只编译一个 EXE”的标准描述

团队文档、任务或沟通中建议统一写成：

> 本次为内部调试构建，仅生成 Windows x64 Release 可执行文件，不制作 MSI、NSIS 安装包或便携版 ZIP。执行 `npm run tauri build -- --no-bundle`，交付产物为 `src-tauri/target/release/sqlconnect.exe`。

这是本项目最适合“只要一个 EXE”的命令，因为它仍会执行 `beforeBuildCommand`，先构建最新前端，再编译并嵌入 Tauri 应用，但通过 `--no-bundle` 跳过安装器生成。

不要把 `cargo build --release` 作为默认的完整应用构建命令：它不会自动执行 `npm run build`，如果 `dist/` 不是最新，生成的 EXE 可能包含旧前端资源。只有确认前端完全没有变化且 `dist/` 已更新时，才可用它缩短纯 Rust 修改的重复编译时间。

## 2. 环境准备

### 2.1 通用环境

- Node.js 18+；GitHub Actions 使用 Node.js 20。
- npm，与 `package-lock.json` 配套使用。
- Rust 1.85+，安装 stable toolchain。
- Git。

### 2.2 Windows 环境

- WebView2 Runtime，现代 Windows 通常已安装。
- Microsoft C++ Build Tools 和 Windows SDK。
- Tauri 生成 MSI/NSIS 所需组件通常由 CLI 自动准备；失败时根据 CLI 日志安装 WiX/NSIS 依赖。

### 2.3 Linux CI 依赖

```bash
sudo apt-get update
sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
```

### 2.4 首次初始化

```powershell
Set-Location E:\KimiData\kimi\Workspaces\SQLConnect\sqlconnect
npm ci
rustc --version
cargo --version
npx tauri --version
```

使用 `npm ci` 保证依赖与锁文件一致。升级依赖时才使用 `npm install` 并审查 `package-lock.json` 的变化。

## 3. 构建前检查

```powershell
git status --short
git log -1 --oneline --decorate
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
```

构建可以包含未提交修改，但交付时必须把以下信息一起写入说明：

- 分支和提交哈希。
- 是否存在未提交修改。
- 未提交修改涉及哪些文件。
- 版本号和构建日期。
- 执行过哪些测试，哪些真实环境测试没有执行。

正式发布前应保证工作区干净；内部调试 EXE 可以来自工作区修改，但文件名或说明中应标记为内部构建，避免被误认为正式版本。

## 4. 版本号同步

正式发版时同步检查：

| 文件 | 字段 |
| --- | --- |
| `package.json` | `version` |
| `src-tauri/Cargo.toml` | `[package].version` |
| `src-tauri/tauri.conf.json` | `version` |
| `src-tauri/Cargo.lock` | 本项目 `sqlconnect` 包的版本 |
| `README.md` | 当前版本、下载说明和路线图 |
| `docs/项目交接文档.md` | 交接基线和验证日期 |
| `docs/对接文档.md` | 接口基线版本和提交 |

修改后检查：

```powershell
rg -n '0\.1\.3|v0\.1\.3' package.json src-tauri README.md docs
```

将示例中的旧版本替换为目标版本，例如 `0.1.4`。标签统一使用带 `v` 的形式，例如 `v0.1.4`；配置文件中的版本不带 `v`。

## 5. 日常开发模式

```powershell
npm run tauri dev
```

该命令启动 Vite 和 Tauri 开发窗口。Vite 默认端口为 `1420`，HMR 在设置 `TAURI_DEV_HOST` 时使用 `1421`。

只运行 `npm run dev` 会启动浏览器前端，但数据库、文件对话框、原生窗口和日志等 Tauri IPC 功能不可完整使用。

## 6. 只生成一个调试 EXE

### 6.1 推荐命令

```powershell
Set-Location E:\KimiData\kimi\Workspaces\SQLConnect\sqlconnect
npm run tauri build -- --no-bundle
```

成功后产物为：

```text
src-tauri/target/release/sqlconnect.exe
```

该命令不会生成以下内容：

- MSI 安装包。
- NSIS `-setup.exe` 安装包。
- 便携版 ZIP。
- GitHub Release。

### 6.2 调试 EXE 验收

```powershell
$exe = 'src-tauri\target\release\sqlconnect.exe'
Get-Item -LiteralPath $exe | Select-Object FullName,Length,LastWriteTime
Get-FileHash -LiteralPath $exe -Algorithm SHA256
```

建议人工验证：

1. 双击 EXE 能启动主窗口。
2. 能打开连接对话框。
3. 至少连接一类本次修改涉及的数据库。
4. 验证被修改的功能路径。
5. 关闭应用后确认进程退出。

如果要把 EXE 发给测试人员，可复制并改为包含版本和架构的名称，但不要修改编译目录中的原文件：

```powershell
$version = '0.1.3'
$source = 'src-tauri\target\release\sqlconnect.exe'
$destination = "src-tauri\target\release\SQLink-v$version-x64-debug.exe"
Copy-Item -LiteralPath $source -Destination $destination -Force
```

## 7. 正式 Windows 打包

```powershell
Set-Location E:\KimiData\kimi\Workspaces\SQLConnect\sqlconnect
npm run tauri build
```

当前 Windows x64 产物路径：

```text
src-tauri/target/release/sqlconnect.exe
src-tauri/target/release/bundle/msi/SQLink_<版本>_x64_en-US.msi
src-tauri/target/release/bundle/nsis/SQLink_<版本>_x64-setup.exe
```

以 `0.1.3` 为例：

```text
src-tauri/target/release/bundle/msi/SQLink_0.1.3_x64_en-US.msi
src-tauri/target/release/bundle/nsis/SQLink_0.1.3_x64-setup.exe
```

NSIS 安装包通常作为 Windows 用户的推荐下载；MSI 可用于偏好 Windows Installer 或企业部署的环境。

## 8. 制作便携版 ZIP

Tauri 本地完整构建不会自动生成便携版 ZIP。便携版只是把 Release EXE 重命名为 `SQLink.exe` 后压缩：

```powershell
$version = '0.1.3'
$releaseDir = (Resolve-Path 'src-tauri\target\release').Path
$portableDir = Join-Path $releaseDir 'portable'
$sourceExe = Join-Path $releaseDir 'sqlconnect.exe'
$portableExe = Join-Path $portableDir 'SQLink.exe'
$zipPath = Join-Path $releaseDir "bundle\SQLink-v$version-portable.zip"

New-Item -ItemType Directory -Force -Path $portableDir | Out-Null
Copy-Item -LiteralPath $sourceExe -Destination $portableExe -Force
Compress-Archive -LiteralPath $portableExe -DestinationPath $zipPath -Force
```

产物：

```text
src-tauri/target/release/bundle/SQLink-v<版本>-portable.zip
```

验证 ZIP 内部文件名：

```powershell
tar -tf "src-tauri\target\release\bundle\SQLink-v$version-portable.zip"
```

预期只包含 `SQLink.exe`。

便携版只是免安装，不代表完全无本地数据。连接配置、密钥、历史和 MCP 配置仍由 Tauri 写入当前用户的应用配置目录。

## 9. 只生成指定安装包

Tauri CLI 支持通过 `--bundles` 限制打包类型：

```powershell
# 只生成 NSIS 安装包
npm run tauri build -- --bundles nsis

# 只生成 MSI
npm run tauri build -- --bundles msi

# 同时生成二者
npm run tauri build -- --bundles msi,nsis
```

如果只是需要 EXE，使用 `--no-bundle`，不要用 `--bundles`。

## 10. 文件校验

### 10.1 大小和时间

```powershell
Get-ChildItem 'src-tauri\target\release\bundle' -Recurse -File |
  Select-Object FullName,Length,LastWriteTime
```

### 10.2 SHA256

```powershell
Get-ChildItem 'src-tauri\target\release\bundle' -Recurse -File |
  ForEach-Object {
    $hash = Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256
    [pscustomobject]@{
      File = $_.Name
      SHA256 = $hash.Hash
    }
  }
```

对外发布时建议把 SHA256 放在 Release 说明或单独的 `SHA256SUMS.txt` 中。

## 11. 代码签名

当前仓库没有配置 Windows 或 macOS 代码签名。检查 Windows 产物：

```powershell
Get-AuthenticodeSignature -LiteralPath `
  'src-tauri\target\release\bundle\nsis\SQLink_0.1.3_x64-setup.exe'
```

返回 `NotSigned` 表示未签名，Windows SmartScreen 可能提示风险。正式对外发布前应：

1. 获取受信任的代码签名证书。
2. 将证书和密码放在受保护的 CI Secret 中，不提交到仓库。
3. 按 Tauri 官方签名方式配置 CI。
4. 对最终安装包验证签名主体、时间戳和证书链。

macOS 当前也未签名和公证，首次打开通常需要右键选择“打开”。

## 12. GitHub Actions 发布

工作流文件：`.github/workflows/release.yml`。

触发方式：

- 推送 `v*` 标签。
- GitHub Actions 页面手工执行 `workflow_dispatch`。

矩阵产物：

- macOS Apple Silicon DMG。
- macOS Intel DMG。
- Linux DEB、AppImage、RPM。
- Windows MSI、NSIS 和便携版 ZIP。

标准发版步骤：

```powershell
# 示例：发 0.1.4
git status --short
git log -1 --oneline
git tag -a v0.1.4 -m "SQLink v0.1.4"
git push origin v0.1.4
```

推送前必须确认目标提交和版本号。标签推送后，工作流会创建草稿 Release；所有矩阵任务完成后，在 Releases 页面检查产物、安装测试和说明，再手工发布草稿。

不要在已有同名标签指向错误提交时强制覆盖远端标签。先停止发布并由仓库负责人决定修复方式。

## 14. 常见构建问题

| 问题 | 处理 |
| --- | --- |
| `1420` 端口被占用 | 结束占用进程；Vite 配置为 `strictPort`，不会自动换端口 |
| WebView2 缺失 | 安装 Microsoft Edge WebView2 Runtime |
| Rust 链接失败 | 检查 C++ Build Tools、Windows SDK 和 Rust target |
| 前端改了但 EXE 还是旧页面 | 不要只运行 `cargo build --release`；使用 Tauri build 命令重新构建前端 |
| 只要 EXE 却开始生成 MSI | 命令缺少 `-- --no-bundle` |
| 安装包显示未知发布者 | 当前未签名；配置代码签名后重新生成最终产物 |
| Vite 提示 chunk 超过 500 KB | 当前主包较大但不阻止构建；后续通过动态加载和 manualChunks 优化 |
| `Shell::open` 弃用警告 | 当前不阻止构建；后续迁移到 `tauri-plugin-opener` |
| bundle identifier 以 `.app` 结尾警告 | 当前标识为 `com.sqlconnect.app`；修改会影响应用数据目录和升级识别，需单独制定迁移方案 |
