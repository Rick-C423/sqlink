# P2 02：流式导出与单租约导入

日期：2026-10-20。沿用现有未提交工作区，不提交、推送、发布或替换现用 EXE；网格编辑的数据库、类型与可信身份限制保持不变。

## 本轮实现

CSV 和 SQL 文件导出通过后端 `ExportJob` 固定连接代次、来源身份、任务 UUID 和目标文件。四驱动的 `SessionLease.stream_export` 逐行交付无损 `TypedValue`；不再物化整表，也不经过网格的 JSON/hex 显示值。空表保留列名。列无法无损解码、出现额外结果集、行列映射错误或超预算时明确失败，不填 NULL、不截断成“成功文件”。

| 预算 | 行为 |
| --- | --- |
| 总行数、文件总字节数 | 没有交互查询的 10,000 行/16 MiB 截断；持续消费并写盘 |
| 原始单元格、原始行 | 分别为 1 MiB、16 MiB；转换前检查，超限失败 |
| 类型化单行持有值 | 最多 32 MiB，包含 Base64 等有限膨胀 |
| SQL INSERT | 同时按 100 行和 8 MiB 拆批；单行无法装入时失败 |
| 导入单行、单条 SQL | 16 MiB；通过 `fill_buf` 有界读取，复制前检查 |
| 导出表目录计划 | 16 MiB；仅保留读取 SQL 与恢复目标，DDL 逐表写临时文件 |
| 旧 `dump_table -> String` 兼容接口 | 总文本 16 MiB，超限要求改用文件导出 |

这些预算限制应用保留的数据与编码，不是进程 RSS 硬上限。驱动可能先解码完整的一个协议行；协议缓冲、数据库执行内存和并发任务另计。本轮未进行峰值 RSS 基准测试。

## 文件与任务边界

导出使用目标同目录、随机名称、`create_new` 创建的临时文件和 64 KiB 缓冲。完成后依次 flush、文件同步、关闭、平台原子替换；Windows 使用 `MoveFileExW` 的替换与写穿标志，不先删除旧文件。正常取消、读取/编码/写盘/替换失败会保留旧目标并清理临时文件。强制进程退出可能留下以 `.sqlink-export-` 标识的未完成文件，但不会发布半成品。替换后的目录同步故障明确说明“文件已替换、持久性未确认”，不能改报旧文件仍在。

目标目录、符号链接和重解析路径会被拒绝。SQLite 通过实际连接的 `PRAGMA database_list` 检查主库、ATTACH 库及 `-wal/-shm/-journal` 文件，读取前与提交前均防止用导出文件覆盖数据源；不采信前端数据库标签。路径检查不承诺抵御恶意进程并发篡改父目录。

导出接入既有 `TaskRegistry`，复用阶段与独占租约。同一多表导出持有一个数据租约；SQL Server 仍不支持运行中取消。未读流发生错误或消费者停止时，MySQL/PG/SQL Server 隔离物理会话而不排空巨大尾部；完整消费后才可继续同租约。取消回执只表示已请求，实际停止、清理与最终文件结果分别报告；清理与原错误同时失败时保留两种原因和未知状态。文件提交阶段拒绝迟到取消。

SQL 导出界面固定原连接、数据库、路径和 UUID，显示真实任务阶段，禁止运行中关闭或改选；旧的表目录、能力或取消响应不能覆盖新来源。CSV 旧入口兼容新增可选 taskId，专用 `export_cancel` 严格核对原连接和导出任务，不能取消其他操作。

## 格式与数据保真

- CSV 为 UTF-8、无 BOM、LF。SQL NULL 为未引用的 `\N`；文本始终加双引号，因此空文本 `""`、文本 `"\N"` 与 NULL 不混淆。整数/精确小数按原十进制输出；二进制为引用的 `\x` 加小写十六进制，空二进制是 `"\x"`。这是明确的导出约定，本轮未新增 CSV 导入器。
- SQL 使用方言编码原值。MySQL 文本用 UTF-8 hex 转换表达式、二进制用二进制字面量，不依赖反斜杠 SQL 模式；PG、SQL Server、SQLite 分别保留对应文本、二进制与数值语义。SQLite 动态存储类中的数值文本不能变成整数，大整数不能经过 JS Number。
- SELECT 始终引用完整源身份。MySQL 恢复 INSERT 不带源数据库名，与 `SHOW CREATE TABLE` 的恢复目标一致；导入另一库时不能写回源库。表名中的换行不会被嵌入未保护的单行注释。
- SQLite/MySQL 保留原始 CREATE，计算生成列不写入 INSERT，由恢复后的数据库计算。PG/MSSQL 的现有 DDL 兼容层不能完整重建 identity/generated，相关 SQL 转储明确拒绝；CSV 仍按可解码原值导出。MySQL TIMESTAMP、扩展 TIME、零日期及各驱动无法无损表达的类型也会明确拒绝，不回退成显示字符串。

多表逐个 SELECT 读取，不承诺整库一致性快照。现有 DDL 转储仍不是完整数据库备份：索引、外键依赖顺序、触发器、权限、扩展类型及全部对象恢复策略没有在本轮统一解决；PG/MSSQL 仍按现有列定义重建兼容 DDL。SQLite temp/ATTACH 的 SQL 恢复目标尚未实现，明确要求改用 CSV。完整元数据流式改造仍属 P2 03；本轮先防止 MySQL 目录截断被当作“全部表”成功导出。

## 导入行为

导入在数据库访问前验证冲突策略及文件可读性，整文件沿用一个租约，保留临时对象、会话设置和显式事务的连续性。拆分器保持已有字符串、注释和 DELIMITER 规则，并增加有界读取、未闭合内容拒绝和带引号标识符回归；不把它当作完整跨方言 SQL 语法解析器。

失败信息列出语句序号、成功数、跳过数和原错误，提示此前成功语句可能已提交，不自动重试。会话清理失败附加报告，不覆盖原错误。成功返回的 `cleanupNotice` 明确：executed 是语句执行成功数，不是所有数据的提交回执；未闭合事务会在归还时回滚。`skip` 仍只跳过已存在表的 CREATE，数据语句继续执行。完整 ImportPlan、事务策略选择和中断恢复检查点仍需后续实现。
