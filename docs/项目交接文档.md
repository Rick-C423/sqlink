## 2. 产品定位与已交付能力

SQLink 是一个轻量级跨平台数据库客户端，核心使用场景是连接管理、数据库对象浏览、SQL 查询、表数据编辑、结构管理和导入导出。

### 2.1 已实现功能

- 保存、编辑、连接、断开和删除数据库连接；密码以 AES-256-GCM 加密落盘。
- 数据库、表、视图、触发器、存储过程、函数、用户及权限信息浏览。
- Monaco SQL 编辑器，支持执行选中/全部 SQL、结果展示、查询历史和部分驱动的查询取消。
- 表数据分页、筛选、行内编辑和事务批量提交。
- 数据网格列宽可拖拽调整（会话内有效），悬停被截断的单元格可在浮层查看完整内容并复制。
- 新建数据库、新建表和已有表结构编辑，按四种数据库方言生成 DDL。
- SQL 文件导入、数据库/表 SQL 转储、整表 CSV 导出。
- 中英文界面、深浅主题、多标签工作台和可调整面板。
- 按天滚动日志、慢查询和失败查询记录。
- 内置仅限本机访问的只读 MCP Streamable HTTP 服务；可在应用内「MCP 设置」中启停服务、修改端口、按工具启用/禁用，并按连接控制访问。

### 2.2 尚未实现或能力不完整

- SQL Server 查询取消。
- SQL 收藏。
- CSV 导入到表。
- ER 关系图。
- 数据同步和结构同步。
- 连接分组 UI；`groupName` 仅在模型中预留。
- 更多数据库驱动，如 Oracle、ClickHouse、Redis。
- macOS 安装包签名与公证。

### 3.3 驱动抽象

`DatabaseDriver` 是扩展数据库类型时的核心契约，主要覆盖：

- 连接状态、查询、执行、取消和断开。
- 数据库、表、列、索引、外键等元数据。
- 视图、触发器、存储过程、函数及其定义。
- 用户和当前用户权限。
- 事务批处理、CSV 导出和 SQL 转储。
- 方言相关的标识符转义。

新增驱动时，除了实现 trait，还必须同步修改驱动工厂、前端连接表单、前端类型、DDL 方言、i18n 和数据库兼容性测试。不能只在工厂里增加一个分支。

## 4. 关键数据流

### 4.1 保存并连接

1. 前端调用 `connection_save`。
2. `ConnectionPoolManager::save_and_connect` 为新连接生成 UUID。
3. `ConnectionStore` 按 `savePassword` 决定是否保存密码；需要保存时使用 AES-256-GCM 加密。
4. 配置写入 `connections.json`。
5. 驱动工厂创建真实连接并放入内存连接表。
6. IPC 只返回连接 ID，不返回密码。

更新连接时，前端传入空密码表示保留原密码；更新后当前活动连接会断开，需要用户重新连接。

### 4.2 查询执行

1. 编辑器固定本次连接、数据库和递增任务 ID；明确的单表查询先通过 `schema_resolve_table` 获取实际库名、schema、表名及列信息，再以完整限定名调用 `query_execute`。
2. 后端按 SQL 首关键字决定走 `query` 还是 `execute`。
3. 驱动返回统一 `QueryResult`。
4. 仅编辑器明确要求记录的成功查询会写入历史。
5. 前端按任务 ID 将结果和来源同时发布到对应标签；旧请求和元数据迟到时不覆盖新任务。所有任意 SQL 结果均只读，候选表解析不再授予编辑权限。

### 4.3 活动连接与自动重连

活动驱动只存在于内存。应用重启或活动连接缺失时，`get_connection` 会尝试从已保存配置解密密码并自动重连。没有保存配置或没有保存密码时，自动重连可能失败并返回“连接已关闭”。

### 4.4 表格编辑

P0 已关闭前端生成 SQL 的网格保存链路：前端策略和旧生成入口拒绝，独立后端命令 `query_apply_grid_edits` 也始终返回 `GRID_EDIT_CONTEXT_REQUIRED`。P1 01 的无筛选表浏览由 `table_read_page` 建立后端结果上下文、直投影字段来源和不透明行句柄；P1 02 新增驱动原值的 typedRows、类型化原行快照、四驱动参数绑定和 `changeset_validate` 预检；P1 03 接入四驱动独占租约、任务注册表和取消状态。P1 04 新增同事务对象/完整旧行核验、参数化提交协调器及独立回执缓存，前端补冻结请求、冲突保留、未知核查和提交后只重试刷新的状态处理。生产 `changeset_commit` 仍固定被凭据恢复和实库门禁拒绝，预检仍 `executable:false`；测试授权不对 IPC 开放，网格继续只读。`query_execute_batch` 仍供手工脚本、结构等显式操作，网格不得调用。候选字段/主键检查、预检或 context 校验均不构成写权限。

取消沿用冻结的执行来源与随机任务 UUID；“请求取消”不代表语句已停止，提交开始后拒绝取消。表浏览读取与统计使用同一份已解析身份。排序通过列元数据规范身份并去重，补齐完整主键，SQL Server 保留 ROW_NUMBER 兼容分页。草稿由独立 store 按结构化页面键保存，脏草稿钉住原结果；导航提供保存、放弃和取消，失败不继续。PG 和 SQL Server 每租约使用独立短连接，MySQL 仅健康归还后允许池复用，SQLite 专属工作线程串行持有租约。SQLite 的 `transactionOnly` 清理保留原逻辑连接的 TEMP/ATTACH/PRAGMA 状态；SQL Server 暂不支持取消。独立执行之间不保留手工 BEGIN，应在同次“执行全部”内完成事务；SQL 导入已固定全文件租约，导入导出统一任务进度及恢复仍属于后续工作。

## 5. 本地数据与配置

应用标识为 `com.sqlconnect.app`。Tauri 根据操作系统解析配置和日志目录；Windows 当前代码注释对应 `%APPDATA%\com.sqlconnect.app`。

| 数据 | 文件/位置 | 生命周期与注意事项 |
| --- | --- | --- |
| 已保存连接 | `{app_config_dir}/connections.json` | 密码为 `enc:v1:<nonce>:<cipher>`，列表 IPC 会清空密码字段 |
| 加密密钥 | 系统钥匙串（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service），条目 `SQLink / connections-key-<配置目录哈希>` | 32 字节 AES 密钥的 base64；旧版本遗留的 `{app_config_dir}/key.bin` 首次运行时自动迁入并删除；钥匙串不可用时回退 key.bin |
| 查询历史 | `{app_config_dir}/history.jsonl` | 超过 600 条时压缩到最近 500 条；列表再按连接过滤 |
| MCP 配置 | `{app_config_dir}/mcp-server.json` | 包含本机 MCP URL 和 Bearer Token，应视为敏感文件 |
| MCP 设置 | `{app_config_dir}/mcp-settings.json` | 启用开关/端口/禁用工具；连接白名单不在本文件，存于 connections.json 的 `mcpAllowed` |
| 日志 | `{app_log_dir}/sqlink.log.YYYY-MM-DD` | 按天滚动，启动时清理 7 天前日志 |
| UI 偏好 | WebView `localStorage` | 包括主题、侧栏宽度、结果区高度、数据库缓存和折叠状态 |

### 5.1 备份与迁移

- 加密密钥存于系统钥匙串后，迁移已保存连接只需带走 `connections.json`；新环境首次运行会生成新密钥，旧密文需重新输入密码。如需保留密码迁移，须在旧环境通过应用正常读取代入新环境（钥匙串条目不可直接复制）。
- 仍处于 key.bin 回退模式（无钥匙串环境）时，`connections.json` 和 `key.bin` 必须成对迁移。
- `mcp-server.json` 含访问令牌，不建议进入普通备份共享包；需要迁移时应安全传输或在新环境重置 Token。
- 删除系统钥匙串中的 `SQLink` 条目（或回退模式下删除/重建 `key.bin`）会让已保存密文不可恢复，只能重新输入密码。
- 清理应用配置目录前先退出 SQLink，并备份整个目录。

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `SQLINK_LOG` | tracing 过滤级别，如 `debug` | `info,sqlconnect=debug` |
| `SQLINK_MCP_PORT` | 内置 MCP 监听端口 | `48123` |

## 6. IPC 对接约定

### 6.2 数据格式约定

- Rust 模型字段通过 serde 转换为 camelCase。
- 数据行使用 `RowData.values`，其顺序与 `QueryResult.columns` 一致。
- 数据库 NULL 通常表现为 `null`/空 Option，不应与空字符串混淆。

- 错误目前主要以中文字符串跨 IPC 返回，不适合稳定的程序化错误码判断。

## 7. MCP 服务交接

SQLink 启动桌面主流程后，会异步尝试启动 MCP；MCP 启动失败不会阻止桌面应用启动。

### 7.1 接入信息

- 地址：`http://127.0.0.1:48123/mcp`（可在「MCP 设置」中修改端口；环境变量 `SQLINK_MCP_PORT` 优先）。
- 协议：Streamable HTTP、无状态 JSON 响应。
- 鉴权：`Authorization: Bearer <token>`。
- 工具：`list_connections`、`list_databases`、`list_tables`、`describe_table`、`query_scalar`、`read_table_rows`、`execute_readonly_sql`；均可逐一禁用。
- 连接白名单：仅「MCP 设置」中勾选允许的连接可被访问（`mcpAllowed` 缺省视为允许）。

完整使用说明见 `docs/MCP工具.md`。

### 7.2 安全限制

- 仅监听 IPv4 回环地址，不对局域网开放。
- 只允许一条以查询类关键字开头的 SQL，并拒绝写入、DDL、事务、过程调用等关键字。
- 默认最多 100 行，调用方最高可请求 1000 行。
- 查询等待上限 30 秒，序列化响应上限 1,000,000 字节。
- MCP 校验只是应用层防线；生产数据库必须再使用只读账号。
- 令牌保存在本机配置文件中。能读取该文件的本机进程理论上可以调用 MCP。

注意：超时实现会停止等待 future，但接手人仍应针对四种驱动确认底层数据库查询是否真正终止，不能把“HTTP 已超时”直接等同于“数据库已取消执行”。

## 10. 构建与发布

本节只保留交接层面的发布约束。具体的环境准备、版本同步、单 EXE 构建、安装包路径、便携版制作、SHA256、签名和 GitHub Release 操作，统一以 `docs/构建与发布操作手册.md` 为准。

### 10.1 版本号同步

发版前至少同步：

- `package.json` 的 `version`。
- `src-tauri/Cargo.toml` 的 `version`。
- `src-tauri/tauri.conf.json` 的 `version`。
- `Cargo.lock` 中本项目包版本（运行 Cargo 命令后检查）。
- README 和交接/对接文档中的版本描述。

三个版本号不一致可能导致安装包名、应用元数据和前端信息不一致。

### 10.2 GitHub Actions 发布流

`.github/workflows/release.yml` 在推送 `v*` 标签时触发，也支持手工触发。矩阵包括：

- macOS Apple Silicon。
- macOS Intel。
- Ubuntu 22.04。
- Windows。

Tauri Action 会创建草稿 Release 并上传安装包；Windows 额外生成便携版 ZIP。所有平台完成后仍需在 GitHub Releases 页面检查文件并手工发布草稿。

建议发布步骤：

1. 确认工作区干净，版本号和文档已同步。
2. 本地执行 `npm run build`、`cargo test`，并完成四数据库冒烟。
3. 合并到 `main`，确认目标提交哈希。
4. 创建与版本一致的标签，例如 `v0.1.4`，推送标签。
5. 检查四个平台任务和草稿 Release 中的产物。
6. 在干净环境安装/启动至少 Windows 和一个其他平台产物。
7. 填写变更说明后发布草稿 Release。

当前 CI 没有代码签名配置；macOS 包未签名，首次打开可能需要用户右键选择“打开”。

## 11. 日志与故障排查

### 11.1 日志获取

- 应用内调用“打开日志目录”。
- Windows 可检查 `%APPDATA%\com.sqlconnect.app\logs`。
- 临时增加日志：在启动进程前设置 `SQLINK_LOG=debug`，必要时可指定更细过滤规则。
- 日志默认同时输出到控制台和按天滚动文件，只保留约 7 天。

日志规范明确禁止记录密码和完整连接串。新增日志只能记录驱动类型、主机、端口、数据库名、耗时和错误摘要等必要元信息。

### 11.2 常见问题

| 现象 | 优先检查 | 处理建议 |
| --- | --- | --- |
| 应用无法启动 | WebView2、日志目录、前端资源是否打包 | 开发模式看控制台；发布包检查 WebView2 和日志 |
| 点击连接后失败 | host/port/TLS/账号/服务端授权 | 用“测试连接”；对照日志但不要粘贴密码 |
| 重启后无法自动连接 | `savePassword`、`connections.json`、系统钥匙串中的 `SQLink` 条目（回退模式为 `key.bin`） | 确认密钥未丢失；必要时删除钥匙串条目并重新输入、保存密码 |
| MySQL 结构页一直加载 | 元数据锁、当前未提交的 15 秒超时修复 | 查 `performance_schema.metadata_locks` 或未提交 DDL；验证补丁 |
| SQL Server TLS 失败 | 连接配置 `encrypt`、服务端 TLS 能力 | 先确认服务端要求，不要盲目信任不安全配置 |
| SQL Server 取消无效 | 当前驱动限制 | 等查询完成/服务端终止会话；后续实现取消能力 |
| MCP 返回 401 | Bearer Token 与当前配置不一致 | 重新读取 `mcp-server.json`，不要公开令牌 |
| MCP 无法启动 | 48123 被占用、配置目录不可写 | 查日志；设置新的 `SQLINK_MCP_PORT` 后重启 |
| MCP 工具列表缺工具或连接不可见 | 「MCP 设置」中的工具开关/连接勾选 | 在设置中重新启用 |
| 历史记录缺失 | 查询是否成功、是否由编辑器要求记录 | 检查 `history.jsonl` 和日志；自动元数据查询不记录 |
| 页面偏好异常 | WebView `localStorage` | 在备份必要数据后清理对应 `sqlink.*` 键 |

## 12. 安全说明

### 12.1 已有保护

- 保存的密码使用 AES-256-GCM 加密；加密密钥存于系统钥匙串（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service），旧 key.bin 首次运行自动迁移，无钥匙串环境回退文件方案。
- 密码不会通过连接列表 IPC 下发前端。
- 日志设计上不记录密码和完整连接串。
- MCP 仅监听本机、要求 Bearer Token、限制 SQL 类型/行数/时间/响应大小。
- Tauri capability 仅开放必要的 dialog 和 `shell.open` 等权限。

### 12.2 安全边界和不足

- 加密密钥已迁移到系统钥匙串（2026-09-07），密钥不再与密文同目录。残余风险：本机用户权限的攻击者仍可读取当前用户钥匙串条目；多套安装（如便携版换目录）各自持有独立条目，目录路径变化视为新环境。
- 内容安全策略（CSP）已配置：`default-src 'self'` 基线，按需放行 Monaco 的内联样式与 blob worker，`connect-src` 限定 Tauri IPC 通道；新增外部资源（CDN 等）时需同步收紧评估。
- MCP Token 以明文存在本机配置文件中，应依赖操作系统用户目录权限保护。
- MCP 只读 SQL 使用词法黑名单/白名单，不是完整 SQL 解析器；必须配合数据库只读账号。
- Tauri SQL 编辑能力本身允许用户执行写 SQL，这是产品功能，不是安全沙箱。

## 14. 修改规范与高风险区域

### 14.1 修改一个 IPC 的检查项

1. 在 Rust command 中实现或调整参数。
2. 在 `lib.rs` 注册命令。
3. 在 `tauriService.ts` 更新封装。
4. 在 `src/types/database.ts` 与 Rust model 同步类型和字段命名。
5. 更新中英文文案。
6. 增加测试，并执行前端构建与 Rust 测试。

### 14.2 修改数据库结构功能的检查项

- 四种数据库的标识符引用规则不同：MySQL 使用反引号，PG/SQLite/SQL Server 实现各有差异。
- 表名、Schema 名和数据库名必须通过驱动转义，不可直接拼接用户输入。
- DDL 默认值不能一律当字符串加引号，需区分函数、表达式、NULL 和字面量。
- SQL Server 大计数应使用 `BIGINT`/`COUNT_BIG`，历史上已有 int 溢出修复。
- PostgreSQL 的 database 与 schema 概念不能混同。
- SQLite 不支持很多直接 ALTER 操作，必要时需重建表。

### 14.3 修改导入/转储的检查项

`database/dump.rs` 的分句器需要正确处理字符串、转义、行注释、块注释及分号。不要用简单 `split(';')` 替代。修改后至少运行现有测试，并补充来源于真实转储文件的回归用例。
