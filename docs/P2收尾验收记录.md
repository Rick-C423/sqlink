## 已实现

- 表页完成读取和可信身份核验即返回，不发送精确 COUNT；以额外一行确定 `hasMore`，统计为用户触发的独立任务，可取消。统计失败、挂起或迟到不会清空当前页或覆盖新来源。
- `DatasetController` 统一页面/统计票据、来源、取消和释放时序，只保留当前页及最多 128 个不透明游标。当前页默认 64 MiB 序列化估算预算；后端游标另有 5 分钟、512 项和 8 MiB 限制。
- 保留 offset 跳页；非空整数/布尔排序及完整主键的受控基础表支持 keyset 连续续页，其余回退并提供原因。刷新失败仍展示旧行，但已释放身份的旧页只读，不能继续统计或编辑。
- SQL 导入先预检有界全文件拆分和 SHA 摘要，冻结连接代次、文件和冲突策略，再在一个独占租约执行。执行期间有阶段/字节/语句进度，支持排队及执行中取消；请求取消与确认终态分开。
- 导入在每次可能发送 SQL 前保存保守执行边界，回执有界持久化且不含 SQL、参数或路径。运行时 taskId 即恢复编号；结束后也可用 runId 查询，跨连接和歧义拒绝。已经发送 SQL 的中断必须人工核对，不按语句序号自动重放。
- 修复 SQL Server 冲突策略错误添加 `CREATE TABLE IF NOT EXISTS`、租约排队取消不响应、迟到取消覆盖真实失败、abort 后内存回执仍停留运行中，以及取消后继续发送下一条脚本的竞争。

网格继续沿用 P1 凭据、数据库版本、对象证据、类型和会话门禁；本轮没有扩大编辑授权。

## 发布前发现并修复的问题

真实 Windows release 窗口两次点击同一 PG 文件预检时退出。应用事件确认 `0xc00000fd`，主线程栈保留 1 MiB；导入扫描原来的 64 KiB 内联数组使预检命令 future 达 66,496 字节。固定缓冲改为直接堆分配，导入 IPC 边界装箱后，命令预检 future 降至 152 字节、执行 future 降至 80 字节；没有增加全局栈或改变导入语义。新增 future 尺寸回归及 1 MiB 窄栈真实预检/执行回归，同一文件的修复版真实桌面复验也成功。失败候选不交付，原应用事件与修复后证据均保留。

桌面回执还暴露默认窗口下页脚按钮被正文挤出的问题。统一 Dialog 改为按视口限制高度、正文独立滚动、页眉与页脚不收缩；前端 221 项回归及生产构建再次通过，默认视口的真实桌面复验通过，800×600 未验收。

## 明确边界与待办

- 各页与统计分别读取，不承诺跨页一致快照；并发修改仍可能引起重复或遗漏。
- 当前 keyset 不支持可空、文本、时间等任意排序；仍可 offset 浏览，不借分页扩大可编辑类型。
- 取数和缓存预算不限制数据库计算量；底层驱动仍可能先分配单个协议行，不能声称整个进程具有同值硬内存上限。
- 任意脚本可能含 DDL、隐式提交及外部副作用。预检不执行 SQL，也不保证所有服务器语法、权限和对象约束正确。
- PostgreSQL COPY、客户端命令和美元引号过程体等不兼容导入格式在预检拒绝。Windows 固定同句柄并禁止共享写入；其他平台仍要求用户确保源文件不被并发改写。
- SQL Server 实库及最终用户 EXE 验收仍待完成；本轮清理、交付、验证与已合并状态均已写入结构化记录。后补的8份脱敏验收文本已补齐提交；39张截图与用户独立稿继续保留本地，没有重试此前被中止的截图上传。
