## 1. 对接架构

```text
React 组件
  └─ Zustand stores
       └─ src/services/tauriService.ts
            └─ invoke("command_name", camelCase 参数)
                 └─ src-tauri/src/commands/*.rs
                      └─ ConnectionPoolManager
                           └─ DatabaseDriver trait
                                ├─ MySQL/MariaDB
                                ├─ PostgreSQL
                                ├─ SQLite
                                └─ SQL Server
```

对接代码的权威来源：

- 前端方法和参数：`src/services/tauriService.ts`。
- 前端类型：`src/types/database.ts`。
- 后端注册列表：`src-tauri/src/lib.rs`。
- 后端命令签名：`src-tauri/src/commands/`。
- 后端序列化模型：`src-tauri/src/models/mod.rs`。
- 驱动契约：`src-tauri/src/database/mod.rs`。

## 2. 通用约定

### 2.1 调用方式

```ts
import { invoke } from "@tauri-apps/api/core";

const result = await invoke<QueryResult>("query_execute", {
  connectionId,
  sql,
  database,
  queryId,
  record: true,
});
```

业务组件不应直接新增散落的 `invoke()`。先在 `tauriService.ts` 增加带类型的方法，再由组件调用。

### 2.2 命名和序列化

- Rust 字段使用 snake_case。
- 共享模型通过 `serde(rename_all = "camelCase")` 输出给前端。
- Tauri command 的前端参数也使用 camelCase，例如 Rust `connection_id` 对应 `connectionId`。
- 命令名保持 snake_case，例如 `schema_get_tables`。
- 前后端新增字段时必须同时修改 Rust model 与 TypeScript interface。

### 2.3 成功和错误

- 后端命令通常返回 `Result<T, String>`。
- 成功值由 Tauri 序列化为 JSON。
- 失败值目前是用户可读字符串，前端通过 Promise reject 接收。
- 旧命令仍有用户可读字符串错误；受控结果/变更接口使用 `{code,message}`，凭据状态另由 `credential_health` 返回。不要依赖中文错误文本做核心业务分支，也不要把凭据读取失败解释为空密码。

### 2.4 数据值

- 查询结果列定义在 `QueryResult.columns`，行值在 `rows[n].values`，按索引一一对应。
- 数据库 NULL 与空字符串必须区分。
- 普通查询的标量整数在 `RowData.values` 序列化时保护：安全范围 `[-9007199254740991,9007199254740991]` 保留 Number，超范围 int64/uint64 使用规范十进制 String；显示和复制禁止转回 Number。后端原值与 SQL 转储字面量类型不变。此规则不递归处理嵌套 JSON，也不改变浮点或行外计数字段。
- 受控表读取另以 `typedRows` 保留大整数十进制文本等无损值，编辑和提交不得从显示值反推类型；普通 SQL 和筛选结果仍不具备可信编辑身份。
- 本地排序仅在整数列元数据明确时使用 BigInt；数字 TEXT 和无声明表达式沿用字符串比较，分页仍由服务端排序。
- P2 01 普通及类型化查询逐行检查 10,000 行、16 MiB 结果字节与 1 MiB 原始单元格预算；字节计入显示/typed 持有与编码估算，不能当作进程 RSS 硬上限。截断时不裁剪值、不发布可编辑身份，详见[P2 01 取数预算验收记录](P2-01取数预算验收记录.md)。
- 日期、时间、Decimal、二进制和驱动特殊类型最终如何显示，以各驱动的 JSON 转换实现为准。

## 3. 核心数据模型

### 3.1 ConnectionConfig

```ts
interface ConnectionConfig {
  id?: string;
  name: string;
  driverType: "mysql" | "mariadb" | "postgres" | "postgresql" |
              "sqlite" | "sqlserver" | "mssql" | string;
  host: string;
  port: number;
  user: string;
  password: string;
  database: string;
  encrypt?: boolean;
  savePassword?: boolean;
  groupName?: string;
  color?: string;
}
```

- `id` 为空时，后端保存连接会生成 UUID。
- `encrypt` 当前主要控制 SQL Server TLS，旧配置缺省按 `false` 处理。
- `savePassword === false` 时密码不落盘。
- 连接列表返回时 `password` 始终为空，不能从列表接口取回明文或密文。
- 更新连接且 `savePassword !== false` 时，`password` 为空表示由存储层保留原密文，不需要先解密；明确设置 `savePassword === false` 则清除落盘密码。
- `groupName` 只做了模型预留，当前没有完整分组 UI。
- SQLite 的文件路径使用 `database` 字段。

### 3.2 QueryResult

```ts
interface QueryResult {
  columns: ColumnMetadata[];
  rows: RowData[];
  totalCount?: number;
  executionTimeMs: number;
  rowsAffected?: number;
  lastInsertId?: number;
  truncated: boolean;
}
```

`ColumnMetadata` 包含 `name`、`dataType`、`unifiedType`、`nullable`、`length?`、`precision?`、`scale?`。

`truncated=true` 表示结果读取提前停止，可能因行数、字节、单元格预算或存在未读后续结果；不可只解释为 10,000 行。`totalCount` 仍为保留行数，零行截断也保留 columns。网络驱动隔离未读物理租约，后续同租约 SQL 会明确失败；关闭连接不承诺服务端已经取消或事务已经回滚。受控表读取超预算返回 `RESULT_BUDGET_EXCEEDED` 而不登记新 context/handles，前端编辑策略亦拒绝 truncated 结果。

注意：当前 Rust `QueryResult` 有 `lastInsertId`，而 TypeScript `QueryResult` 尚未声明该字段；如果前端要使用插入 ID，应先修复类型差异。

`tableParts` 是逐段解码后的标识符数组，段内的点号和引号必须保留，不可再次按点号拆分。MySQL 支持 `table`、`database.table`；PostgreSQL 支持 `table`、`schema.table` 和同库三段名；SQL Server 支持至多三段；SQLite 支持 `table`、`schema.table`。未限定 schema 时由数据库实际解析。返回的 `database` 为目标表所在库，可能不同于查询的默认库；SQLite 的 `database` 保留文件上下文、`schema` 标识 main/temp/附加库。

前端手工执行仍采用当前全局选择；执行开始后固定 `QueryExecution` 和独立 backendTaskId UUID。候选单表查询先解析并固定读取身份，此解析不能授予写权限。任意 SQL 结果不再产生 `EditContext`；无筛选表浏览通过下述受控协议获得可信列来源和后端行句柄，筛选结果仍走普通只读查询。类型化网格已接通 `changeset_commit/changeset_receipt`，仅在后端明确发布允许的操作和列输入类型时开放首批编辑。旧前端写 SQL 生成入口继续拒绝，网格不能回退到 `query_execute_batch`。手工 SQL 脚本和结构操作仍可显式执行。单句与批执行取消都使用冻结来源/任务引用，迟到结果和旧取消失败不能覆盖新任务。

草稿使用结构化页面键在内存保存，包含原结果、原上下文和尚未失焦的输入；排序、翻页、筛选、刷新、重跑和关闭经过统一导航守卫。脏草稿不绑定后来结果，保存失败保留草稿和错误并停止导航。候选字段/主键检查只是诊断，不能替代后端可信写入授权。

#### 受控表结果协议 v1（P1 01）

`TablePageRequest` 为 `{protocolVersion: 1, connectionId, database, tableParts[], page, pageSize, sort?: {column, direction}}`。页码从 1 开始，每页 1–1000 行，方向仅 `asc/desc`。请求不接受原始 SQL、前端主键、列来源或连接代次，未知字段在反序列化时拒绝。排序字段从真实目录规范匹配，补齐完整主键并按列身份去重；读取显式投影目录列。SQLite 的 `database` 来源固定为后端配置文件上下文，`schema` 保留 main/temp/附加库身份，选中 main 时不被 temp 同名表遮蔽。

响应 `TablePage` 为 `{result: QueryResult, context: ResultContext, rowHandles: (string|null)[], table: ResolvedTable, totalRows: number|null, typedRows: (TypedValue|null)[][]}`。显示行、类型化行与句柄按下标一一对应；没有可靠主键或类型不受支持时句柄为 null。每次读取产生新的随机 `resultId`，初始 `revision=1`，不重绑定已有结果。前端 `QueryResult.resultContext/rowHandles/typedRows` 是本地附加字段，普通 `query_execute` 不返回这些字段。前端仅在受控响应独立通道存在并通过校验时附加 typedRows，不能从显示值推断。

P2 收尾将所有表页的 `totalRows` 改为 null。新 `DatasetPage` 在上述字段之外提供 `hasMore/nextCursor/paginationMode/observedOrder/approxBytes/truncatedReason/paginationFallbackReason`。页数据及可信身份核验完成即返回；精确统计须显式调用 `table_count`，返回带原 resultId、revision、connectionId、connectionGeneration 的十进制文本 totalRows。统计挂起、失败或取消不清空已展示页面。取消只记录请求，终态以数据库确认和任务回执为准。

`DatasetController` 只保留当前页，默认 64 MiB 序列化估算预算，历史最多保留 128 个续页令牌；该预算不等于应用 RSS 上限。相邻下一页可使用后端不透明游标，上一页和跳页保留 offset。后端游标按来源、代次、完整对象、元数据指纹、排序、页大小、原上下文及类型化锚点绑定，5 分钟失效，最多 512 项/8 MiB。目前只有可靠完整主键和非空整数/布尔排序开放 keyset，其余在 `paginationFallbackReason` 说明回退；读取预算失败不会发布可编辑上下文。筛选结果继续只读，独立统计不授予网格权限。

`ResultContext` 包含 `protocolVersion/resultId/revision/connectionId/connectionGeneration/source/columns/editPolicy/createdAt/expiresAt`。`source` 为结构化 database/schema/table/kind；列含随机 `columnId`、显示名、数据库类型、可空性、真实对象字段来源及 generated 标记。`editPolicy` 另含 `columnInputKinds`，将后端列 ID 映射到已开放的类型化输入种类。只有凭据健康、对象证据、真实键、会话条件和整表类型范围全部满足时才发布 `allowedOperations=[insert,update,delete]`；可编辑列为 `writable=true`，生成列仍为 false。其它情况保持空操作集合并通过 `reasonCodes` 说明；成功建立行身份本身不授予写权限。

用于定位的键映射和后端留存快照不会作为身份字段下发；随机行句柄不可由显示值或行号推导。P1 02 已将受控读取改为驱动原值解码，原行快照保存 `TypedValue`；None 代表未支持的无损类型，不能用旧显示占位补齐。公开 typedRows 包含本页可无损表达的单元格值，但不接受前端将其作为原始身份或 WHERE 条件回传。主键白名单仍限已核对整数/布尔类型，SQLite 要求真实 Integer；文本、decimal、浮点与时间主键尚不放行。

结果登记表默认 TTL 30 分钟、128 个结果、100000 个行位置及 64 MiB 保守留存预算（包含无句柄行）；超单结果预算拒绝，满容量淘汰最旧结果，访问时清理过期记录。前端关闭/替换干净结果会释放，脏草稿保留原引用与输入；过期或淘汰不清空前端草稿。此预算约束后端留存，不代表驱动取数峰值或前端总内存已有边界。

新命令的错误为 `{code,message}`。包括 `UNSUPPORTED_PROTOCOL`、`RESULT_CONTEXT_EXPIRED`、`RESULT_CONTEXT_NOT_FOUND`、`STALE_REVISION`、`INVALID_ROW_HANDLE`、`CONNECTION_CHANGED`、`STALE_CONNECTION_GENERATION`、`METADATA_CHANGED`、`CONTEXT_BUDGET_EXCEEDED`；前端显示可读消息及原因码。校验接口只还原已登记连接，不能通过旧引用自动重连，也不能接受前端传入的库表覆盖来源。

连接代次覆盖管理器中的逻辑连接替换、断开与自动建连，前端另用本地 epoch 丢弃断开/重连前的迟到响应；它不等价于池内每条物理会话的租约代次。P1 01 的结构指纹只能检测映射变化；P1 04 已在支持的适配器中增加后端对象令牌、同租约事务与对象锁，提交时重新核对同名重建及 DDL 变化。SQLite `main` 以外对象仍不放行，不承诺任意外部恶意目录计数伪造的检测。单独调用 `result_context_validate` 仍不能作为提交授权。

#### 类型化值与参数化变更预检（P1 02）

`TypedValue` 采用 `{kind, value}` 标签：`null` 无 value；`text/boolean/float` 分别携带字符串、布尔和有限浮点；`int64/uint64/decimal` 携带十进制字符串，整数检查真实 64 位范围，不接受指数、前导零或负零，小数保留 scale。`binary` 的 value 为规范 Base64；`date` 为 `YYYY-MM-DD`；`time` 为 `{value: HH:mm:ss[.fraction], precision: 0..9}`；`timestamp` 为 `{value: 日期T时间[Z或偏移], precision, timezone: none|offset}`，时区与精度必须匹配。单元格文本/二进制最多 1 MiB，decimal 最多 1024 字节。外层 typedRows 的 null 表示不支持无损读取，SQL NULL 使用 `{kind:"null"}`。

DEFAULT 是独立的 `CellInput`：`{mode:"set", value:TypedValue}` 或 `{mode:"default"}`，不能作为读取值。空文本、文本“NULL”、空二进制、零和 SQL NULL 分开表达；不从用户输入字符串猜测类型。

`ChangeSetRequest` 为 `{protocolVersion:1, changeSetId, resultId, revision, operations[]}`。insert 包含 `{opId,kind:"insert",changes:{columnId:CellInput}}`；update 另需 rowHandle；delete 仅 `{opId,kind:"delete",rowHandle}`。所有引用来自原结果，不接受 connectionId、库表、原始 SQL、主键或自造 WHERE。操作/行引用不能重复，拒绝重复 JSON 列键；单组 1–1000 个操作，最多 2000 个参数/语句，并有 8 MiB 变更值留存预算。

后端重新检查连接代次、目录指纹、原句柄、字段来源、生成/identity/版本列、可空性、整数范围、decimal precision/scale、文本/字节长度和时间精度。负 scale 的 numeric 当前拒绝；MySQL unsigned decimal 拒绝负值。insert 的 DEFAULT 通过省略列表达，空插入用方言默认插入；SQLite UPDATE DEFAULT 拒绝。所有标识符来自原上下文元数据，值使用驱动原生参数；内部计划不实现 Serialize，不返回 SQL、参数、真实键或原快照。

`changeset_validate` 只返回 `{changeSetId,resultId,revision,operationCount,executable:false,reasonCodes[]}`。预检不会执行 DML，不是提交回执，也不提供提交幂等性。其诊断仍列出 `SESSION_LEASE_REQUIRED/OBJECT_IDENTITY_REQUIRED/COMMIT_RECEIPT_REQUIRED/CREDENTIAL_RECOVERY_REQUIRED/DRIVER_WRITE_VALIDATION_REQUIRED`，表示预检本身不提供这些提交阶段事实，不等于公开提交入口恒拒绝。预检不改变上下文已有授权；实际写入必须经过 `changeset_commit`，旧拼 SQL 入口继续拒绝。

`query_typed/execute_bound` 仅是后端内部基础接口，不是 IPC，也不是任意 SQL 安全沙箱。P1 03 已让这些驱动入口使用独占租约；多语句事务须显式持有同一 SessionLease。MSSQL 仅能检查显式分隔的多句；受控计划按构造产生单条 DML，不接受用户 SQL。P1 04 的公开协调器已按下文首批范围执行凭据/授权、对象/行核验和提交回执。底层绑定范围比网格开放范围更宽，不能据此扩大整表类型白名单。四驱动真实回环验收必须分别记录，网络测试默认显式忽略，编译通过不等于实库通过。

#### 独占会话与任务生命周期（P1 03）

`SessionLease` 是后端拥有的单物理会话租约，包含随机 sessionId、query/execute、类型化读取/绑定、begin/commit/rollback/release。事务所有步骤均使用同一租约，其他任务与元数据不能插入；未正常归还的租约必须回滚、关闭或隔离。普通驱动查询、类型化调用和旧 execute_batch 均进入租约路径。PG/MySQL 借用中的 SQL future 被丢弃后，租约拒绝一切后续 SQL/事务操作并隔离；正常返回的 SQL 错误仍允许显式回滚。取消句柄只对当前租约有效；release 去活并与在途取消串行后才可能复用，旧句柄不能中断下一租约。

`SessionCapabilities` 为 `{cancellation,cancellationReason,exclusiveSession,resetPolicy}`。PG 每租约独立物理 Client、SQL Server 每租约独立 TDS，当前以关闭保证隔离，不能声称已有物理连接池复用；它们的元数据客户端与事务租约独立。MySQL 健康归还执行 ROLLBACK 和 COM_CHANGE_USER 恢复初始库与会话状态，再由池复用；错误、取消或 future 中断隔离 Conn。SQLite 使用专属工作线程与异步独占 gate，取消经独立 InterruptHandle 和受当前 UUID 保护的 progress 回调，SQL 返回后才解除执行标记，清理失败不重建内存库冒充原连接。

full 策略清理或关闭整个物理会话。SQLite 为 transactionOnly：确保事务清理和不交错，保留用户已有的 TEMP/ATTACH/PRAGMA 逻辑连接状态，不能把它当作默认约束设置已恢复；后续受控写入仍需核验相关状态。PG/SQL Server 临时对象仅在同租约内可靠连续；SQL Server 原生参数执行经 RPC，临时表创建/会话级 SET 需要 raw query 的 SQL batch 作用域，不能将所有 RPC 都声称具有相同作用域。

编辑器查询与批执行由 TaskRegistry 登记：queued → preparing → running → committing → succeeded/failed/cancelled/unknown。cancelRequested 独立于 phase；取消请求最多等待 5 秒，超时不表示服务端已停止。SQL Server cancellation=false，执行中请求会拒绝，前端按钮禁用；客户端关闭或断连同样不能冒称服务端已停止。排队准备时确认尚未执行 SQL 的任务可取消而不等待其他租约释放。

`TaskSnapshot` 含 protocolVersion、taskId、queryId、connectionId、connectionGeneration、operation、phase、sequence、cancelRequested、capabilities、sessionId、startedAt/completedAt、commitState、rollbackState、cleanupState、errorCode，以及可选 progress（stage、processedBytes、totalBytes、processedStatements）。进度不包含 SQL、参数或文件路径。默认最多 128 个活动任务，终态访问时按 5 分钟 TTL 与 256 条预算回收，SQL/参数不入登记表。新前端为单次与批次生成独立 UUID，数字 queryId 保留兼容；旧式无 UUID 的取消只能查旧式任务，不能降级取消新 UUID 任务，仍保留的查询 ID/任务 ID 不能重绑定。

COMMIT 发出前取消会先回滚；COMMIT 附近断线或 future Drop 保留 unknown，不自动重发。COMMIT 已确认后立即同步登记 committed，再等待清理；清理失败/中断只改变 cleanupState，不能改报未保存。SQLite 已确认自动提交成功的单条写入也不能因迟到取消改报 cancelled；只有实际中断、未执行或回滚已确认才能给相应结论。任务 Drop/panic 清除活动登记，租约负责物理清理；无法确认清理时显式保留未知状态。

单次执行结束会清理未提交事务，跨多次独立点击不保留 BEGIN；需在同一次“执行全部”中完成事务脚本。含显式事务控制、DDL、MySQL 非事务对象或其他外部副作用的脚本，不按通用批处理承诺全成全败。SQL 导入全文件固定一个租约，失败后仍可能部分提交。P2 已增加冻结计划、预检、任务取消和持久回执；恢复范围仅为安全重试尚未发送的运行，已经发送 SQL 的中断必须人工核对，不能按语句编号自动重放。

P1 03 本身不解决对象重建和冲突/回执；以下 P1 04 增加相应核验。S1 凭据保护已接入，公开网格写入按凭据健康和适配器范围逐次判断。网络会话用例 `session_pg_mysql/session_mssql` 显式 ignored；CI 已配置 PG 17 与 MySQL 8.4 服务及显式实库用例，工作流尚未在 GitHub 运行。本轮显式运行 MySQL 8.4/5.7 与 PG 17 会话测试通过，SQL Server 用户明确无测试实例，继续只读。

#### 对象核验、冲突与提交回执（P1 04）

受控表读取在支持的适配器上使用同一租约事务：检查对象、读取原始类型值、再次检查对象。后端保存对象令牌的 SHA256，令牌不下发。目录核验不支持或缺权限时退回只读读取，结果不能用于可信提交。证据、凭据和类型范围均满足时才发布列级 `writable` 与操作授权；前端不能自行将只读上下文改为可写。

内部提交顺序为：变更形状/预算校验 → ID 原子预留 → 固定原连接代次与任务 → 同一租约 begin_write → 锁定并复核对象/完整列映射 → 按完整后端主键锁定全部原行并比较全部 TypedValue → 参数化执行 → 影响行数核验 → 消费原上下文 → COMMIT → 归还与回执。SQLite 使用 BEGIN IMMEDIATE；PG 显式对象锁和 FOR UPDATE；SQL Server 使用事务表锁及更新锁；MySQL 使用事务 MDL/锁定读。不能在租约内调用另一个 driver.resolve_table 冒充同会话目录核验。

原行任一列为不支持的无损值时拒绝提交；SQL NULL 与文本 NULL、二进制及 int64 均按标签比较。0 行为 ROW_DELETED，现值不符为 ROW_CHANGED，多行命中或影响行数异常均回滚。精确同值 update 不发 DML，记录 matchedRows=1、affectedRows=0、unchanged；MySQL 已确认锁定匹配后返回0的语义保留为无变化，本轮已在 8.4.11 完整提交测试中核对。完整旧值比较检测当前值冲突，不承诺识别删除重插同值或修改后恢复等所有 ABA 历史。

`CommitReceipt` 字段为 `{protocolVersion:1,changeSetId,resultId,revision,connectionId,connectionGeneration,taskId,status,commitState,rollbackState,cleanupState,refreshState,operationResults,errorCode,reasonCodes,completedAt}`。status 为 committed/conflict/rolledBack/failedBeforeCommit/unknown；refreshState 为 notRequested/required。每项操作包含 `{opId,outcome,matchedRows,affectedRows,errorCode,currentValues?}`，outcome 为 applied/unchanged/conflict/rolledBack/notExecuted/unknown。冲突现值总载荷最多64KiB，否则省略；不返回 SQL、绑定参数或真实键映射。

提交前失败即使已成功回滚空事务，也可返回 failedBeforeCommit/notStarted/rollback=succeeded。只有回滚与归还都确认成功才给已知回滚/冲突；否则保留 unknown。COMMIT 附近丢回执或 future 中断不自动重发；活动提交及 unknown/committed 会占用或消费原结果上下文，换 changeSetId 也不能重放，回执详情过期不解除这一保护。COMMIT 成功立即同步登记 committed，再等待归还；归还失败/中断只更新 cleanupState，不能把已提交数据改报未保存。

回执按规范化 changeSetId 原子预留，并散列完整请求；同 ID 不同内容拒绝，并行重复不再执行。详情留存30分钟、总预算16MiB，预留完整基础回执加结果余量；ID/摘要墓碑最多4096个并保留到进程退出，详情过期也拒绝重放。容量不足在 SQL 前拒绝新变更。进程重启后无持久提交账本，旧结果引用失效，不能承诺跨崩溃 exactly once 或将“查不到回执”理解为未提交。回执查询校验原 resultId/revision，不依赖原上下文仍存在。

前端保存流程独立于旧拼 SQL：保存开始冻结原请求和上下文，严格核对回执身份、全部 opId 和事务状态；conflict/rolledBack/failedBeforeCommit 保留输入，unknown 或损坏/丢失响应保留稳定 ID，仅查询原回执。committed 先清已提交输入，刷新失败记 committedRefreshFailed，只调用读取重试。异步结果按提交 token 隔离，保存、核查和刷新期间不允许旧响应覆盖新草稿。DataGrid/TableView 已接通结构化类型输入、完整变更集与上述回执状态，普通 SQL/筛选上下文及任何未授权列仍保持只读。

公开 `changeset_commit` 要求 `credential_health.state=ready`、原上下文的允许操作及列输入种类，并在同一租约重新核对对象和会话条件；缺项分别返回凭据、类型、权限或适配器原因。内部测试绕过参数仍只用于模块测试，不由 IPC、配置或环境变量暴露。

| SQLite | `main` 基础表；按 SQLite 实际顺序计算的 INTEGER、TEXT、BLOB、REAL affinity，写入值须保持原存储类型 | 无触发器，外键及约束 PRAGMA 必须安全；NUMERIC affinity、隐藏/虚拟对象、TEMP/ATTACH 等不开放；使用 `INSERT/UPDATE OR ABORT` 覆盖表定义中的忽略/替换冲突策略，约束失败整批回滚 |
| PostgreSQL | 仅 17；`bigint`、`varchar`/`character varying`、`text`、`bytea` | 分区/继承、临时表、触发器、规则、RLS 等拒绝；其它类型即使底层已支持绑定，当前整表仍只读 |
| MySQL | 仅 8.4 InnoDB；有符号 `bigint`、`varchar`、`varbinary` | 必须证明当前账号的精确 schema 或 table 直接 `TRIGGER` 授权，显式 `USE` 后核对完整触发器目录；全局授权或零个可见触发器不能单独证明可见性。非 strict、会话/列字符集非兼容 utf8mb4、禁用 FK/`unique_checks`、存在触发器等拒绝 |
| SQL Server、MariaDB、MySQL 5.7/其他未验版本 | 未开放网格写入 | SQL Server 缺少实库验收；不能用其它驱动通过替代；MySQL 8.0 有部分对象目录基础设施，但不在本轮公开写入版本范围 |

整表出现任一未开放列类型时保持只读；生成/identity/自增列即使属于已支持类型也保持列级只读。SQLite 同连接 authorizer 代次可检测 DDL 后手动重置 schema_version，不能检测任意外部恶意目录计数伪造。MySQL 8.4.11 与 PostgreSQL 17.11 的完整提交及持有会话权限变化已实测；这不代表所有数据库版本、取消路径或桌面流程均已验收。

SQLite 不支持的过程/函数等能力通常返回空列表或明确错误，调用方不应假设四种驱动的对象能力完全相同。

## 5. ConnectionPoolManager 行为

- 活动连接以 `connectionId -> Arc<dyn DatabaseDriver>` 保存在内存。
- 同 ID 重新连接时会先断开旧连接。
- 找不到活动连接时，会尝试读取已保存配置并自动重连。
- 未保存配置、未保存密码或密钥损坏时，自动重连可能失败。
- 删除已保存连接时会同时尝试断开活动连接。
- 更新已保存连接后会断开原活动连接，前端需要重新连接。

连接密码落盘格式为 `enc:v1:<nonce>:<cipher>`，使用 AES-256-GCM；密钥优先存入系统钥匙串，`key.bin` 只用于旧材料迁移或明确不支持持久化系统钥匙串的平台回退。密码、密文和密钥不得通过 IPC 暴露给前端。

### 5.1 凭据保护与恢复状态（S1）

`credential_health` 无参数，返回 `{state,backend,message}`。健康时 `state=ready`，`backend` 为 `keychain` 或 `file`；故障时可能为 `missing/permission/unavailable/corrupt/conflict/unsupported/io`，并带恢复提示。该接口只读取当前存储实例的状态，不进行换钥、重置或自动恢复。前端类型位于 `src/types/credential.ts`，统一通过 `tauriService.getCredentialHealth()` 获取；连接树和连接编辑框共用独立状态，状态 IPC 失败不会清空已载入的连接元数据。

只有真实 `NoEntry` 才表示钥匙串条目不存在，平台服务故障、访问拒绝、编码损坏和多条目冲突均停止密码操作，不会据此创建 `key.bin` 或替代密钥。Windows 原生错误码区分访问拒绝和登录会话不可用；`keyring` 的一般 `NoStorageAccess` 不能可靠拆分锁定与权限，当前以 `permission` 明确提示“已锁定或无访问权限”，不依赖猜测错误文本重建凭据。前端兼容 `locked/migration_pending` 提示，不将它们宣称为系统钥匙串必然提供的独立原生错误码。

初始化新密钥要求没有旧密钥和迁移记录，连接文件缺失或可解析为空列表；已有非空配置却缺少原密钥时返回 `missing`。损坏的 `key.bin`、钥匙串内容或迁移记录不会被自动覆盖。旧 `key.bin` 迁移复用同一把密钥，依次验证所有旧密文、写入钥匙串、回读比较、原子持久化 `credentials-state.json` 后才清理旧文件；中断后按持久化指针继续核对。两处密钥或指纹不一致时保留所有材料并停止迁移。nonce 必须为 12 字节，损坏长度返回错误，不会 panic。

连接配置读改写使用进程间文件锁和同目录临时文件：写入及同步成功后才原子替换，Windows 使用已依赖的 `MoveFileExW` 替换与写穿标志。写入、同步、替换和迁移清理错误均上报；空白或无法解析的旧配置不当作空列表覆盖。凭据故障时仍可读取可解析的元数据，编辑名称等信息且密码留空会原样保留旧密文；显式取消记住密码才清除落盘密码。保存新密码或解密旧密文会明确失败，不能把失败转为空字符串重新保存。

恢复原钥匙串条目、配套备份或目录访问权限后需重启应用重新核对。Windows 的真实迁移测试使用专用随机服务/账户，验证回读、旧密文及重启行为后清理；既有 MCP 测试也限制为随机临时目录派生的隔离账户并确认删除，测试日志不打印秘密材料。平台实测记录见[《P1 实库验收记录》](P1实库验收记录.md)，桌面提示与交互状态见[《P1 桌面验收记录》](P1桌面验收记录.md)。

## 6. DatabaseDriver 对接

驱动 trait 覆盖连接、查询、Schema、对象定义、用户、事务批处理、CSV、转储和标识符转义。新增数据库驱动需要完成：

1. 在 `src-tauri/src/database/` 新增驱动模块并完整实现 `DatabaseDriver`。
2. 在 `database/mod.rs` 导出模块。
3. 在 `test_connection()` 和 `create_and_connect_driver()` 注册驱动别名。
4. 扩展 `ConnectionConfig.driverType` 和连接对话框默认端口/字段。
5. 在 `src/lib/ddl.ts` 实现建库、建表和 ALTER 方言。
6. 扩展对象树的系统库、Schema 和能力判断。
7. 补充 `zh-CN.ts` 与 `en-US.ts`。
8. 建立真实数据库集成测试，覆盖查询、写入、取消、Schema、导入导出和特殊类型。

### 6.1 方言注意事项

- 所有数据库、Schema、表和列标识符必须调用驱动的 `escape_identifier` 或等价安全方法。
- 值优先使用参数绑定；无法参数化的 DDL 必须严格区分标识符和值。
- PostgreSQL 的 database 和 schema 不可混同。
- SQL Server 大计数使用 `COUNT_BIG` 或先转 `BIGINT`。
- SQLite 的 ALTER 能力受限，复杂结构调整可能需要重建表。
- MySQL/MariaDB 需要考虑字符集、GBK/GB18030 和元数据锁。

## 7. 新增或修改 IPC 的标准步骤

1. 明确是否可以复用已有命令或模型。
2. 修改或新增 Rust model，确认 serde 字段名。
3. 在 `commands/` 实现命令。
4. 在 `src-tauri/src/lib.rs` 注册命令。
5. 更新 `src/types/database.ts`。
6. 在 `src/services/tauriService.ts` 增加统一封装。
7. 由组件或 store 调用 service。
8. 同步中英文文案。
9. 增加 Rust、前端或集成测试。
10. 执行 `npm run build` 和 `cargo test --manifest-path src-tauri/Cargo.toml`。
11. 更新本文档的命令数量、参数和模型说明。

## 8. 对接安全红线

- 不新增返回明文密码、加密密码或密钥的命令。
- 不在日志中记录密码、Token、完整连接串或包含敏感值的完整 SQL。
- 不直接拼接未经转义的标识符。
- 不把 MCP 的词法只读检查当成数据库权限控制。
- 文件权限变化时同步审查 `src-tauri/capabilities/main.json`。
- 修改错误结构时必须考虑旧前端兼容，不要直接改变所有 `Result<T, String>` 的语义。
