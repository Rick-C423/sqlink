## 1. 项目概览

SQLink 是一个轻量、快速、跨平台的数据库客户端，基于 Tauri 2 构建（Rust 后端 + WebView 前端）。相比 Electron 方案安装包更小、内存更低、启动更快。界面聚焦日常数据库浏览、查询和编辑。

**支持的数据库（四驱动均已落地）：**

| 数据库 | 驱动 | 说明 |
| --- | --- | --- |
| MySQL / MariaDB | `mysql_async` | 支持 GBK/GB18030 老库列解码 |
| PostgreSQL | `tokio-postgres` | 跨库惰性连接缓存、查询取消（CancelToken） |
| SQLite | `rusqlite`（bundled） | 本地文件库，支持查询中断（interrupt） |
| SQL Server | `tiberius`（TDS 协议） | rustls 加密、信任自签名证书；老版本 TLS 握手失败自动降级不加密重试；**暂不支持取消查询** |

## 3. 已实现功能清单

### 3.1 连接管理
- 连接树扁平化展示，点击未连接配置自动建连
- 连接配置本地持久化，密码 **AES-256-GCM 加密**落盘，永不下发前端
- 系统数据库（`information_schema` / `master` / `template0` 等）默认隐藏，可切换显示；系统库禁止新建表、导入、删除等危险操作
- 连接颜色标记（渲染在服务器图标上），旁边圆点表示连接状态（绿=已连接，灰=未连接）
- 连接编辑、断开、删除

### 3.2 服务器与用户管理
- 服务器概览页：实例的数据库列表（字符集/排序规则/表数量/大小，四驱动适配）与登录用户列表
- 用户管理：查看各库用户/登录名及权限（MySQL `SHOW GRANTS` 等）
- 可视化权限编辑器：勾选式全局/库级权限管理，保存时自动生成 GRANT / REVOKE；不支持的驱动回退为只读权限文本

### 3.3 数据浏览与编辑
- 表数据网格：分页浏览（20/50/100，默认 20）、行数统计
- 可视化筛选栏：多条件组合（等于/包含/大于/为空等）
- 单表 SELECT 结果集网格内直接编辑，事务批量提交、失败整体回滚
- 数据与结构独立刷新；右键"查数据/编辑结构"直达对应子页

### 3.4 结构管理
- 新建数据库对话框（按方言生成：MySQL 字符集 / PG 编码 / SQL Server 排序规则）
- 可视化新建表设计器：列、索引、外键、主键、默认值、注释，实时 SQL 预览
- 已有表结构编辑（ALTER），按数据库方言生成语句
- 索引 / 外键 / 列注释查看

### 3.5 对象浏览（四驱动适配）
- 视图：树内分组、只读数据浏览、视图定义查看
- 触发器 / 存储过程 / 函数：树浏览与定义查看

### 3.6 SQL 编辑器
- Monaco 编辑器：SQL 高亮、自动补全
- 执行选中 / 执行全部；查询取消（MySQL KILL QUERY / PG CancelToken / SQLite interrupt；SQL Server 暂不支持）
- 执行耗时、影响行数、截断提示
- 查询历史面板：成功语句按连接记录（时间/耗时/行数），点击回填，支持删单条与清空

### 3.7 导入导出
- 导入 SQL 文件：流式拆分大文件（正确处理字符串、注释中的分号），支持"覆盖已存在的表"策略
- 转储 SQL 文件：整库或单表导出 DDL + INSERT（分批 100 行/条）
- 导出 CSV：整表导出，不受查询行数上限限制

### 3.8 界面与体验
- 中英双语一键切换；深色/浅色主题，Windows 系统标题栏随主题联动
- 工作台多标签页：空间不足先压缩，极限后出现左右移动按钮；标签右键（关闭/关闭其他/关闭全部）
- 面板分隔条拖拽（侧栏左右 / 查询结果区上下，双击恢复默认，尺寸持久化）
- 全局禁用 WebView 默认右键菜单，应用内右键均为功能菜单

### 3.9 可观测性
- tracing 滚动日志，记录慢查询与失败查询，支持一键打开日志目录

## 4. 对接接口

### 4.1 总体架构

```
┌────────────────────────────┐        Tauri IPC (invoke)        ┌─────────────────────────────┐
│  前端 React (src/)          │  ─────────────────────────────▶  │  后端 Rust (src-tauri/src/)    │
│  services/tauriService.ts   │  JSON, camelCase 序列化          │  commands/ → database/        │
│  stores/ (Zustand)          │  ◀─────────────────────────────  │  DatabaseDriver trait × 4 驱动 │
└────────────────────────────┘        Result<T, String>          └─────────────────────────────┘
```

- 前端统一通过 `src/services/tauriService.ts` 封装 `invoke()` 调用，状态由 Zustand 四个 store 管理（connection / editor / workspace / theme）。
- 后端入口 `src-tauri/src/lib.rs`，启动时初始化日志与 `ConnectionPoolManager`（连接池 + 本地持久化存储）。
- 所有数据模型 `serde(rename_all = "camelCase")`，前端拿到的字段均为 camelCase。
- 错误统一序列化为字符串（`DatabaseError` 的中文描述），前端按 reject 的 message 展示。

### 4.3 核心数据模型（`src-tauri/src/models/mod.rs`）

- `ConnectionConfig`：id?, name, driverType, host, port, user, password, database?, savePassword?, groupName?（分组预留）, color?
- `QueryResult`：columns[], rows[], totalCount?, executionTimeMs, rowsAffected?, lastInsertId?, truncated
- `ColumnMetadata`：name, dataType, unifiedType, nullable, length?, precision?, scale?
- `TableInfo` / `ColumnInfo` / `IndexInfo` / `ForeignKeyInfo`：Schema 元数据
- `HistoryEntry`：id, connectionId, database?, sql, executedAt（epoch ms）, durationMs, rowCount?, truncated
- `ImportSummary`（statements / executed / skipped）、`DumpSummary`（tables / rows）
- `DbUserInfo`（name, host?, note?）、`CurrentUserInfo`（user, grants[]）
- `DatabaseError`：ConnectionError / QueryError / ExecuteError / TypeError / ConnectionClosed / QueryCancelled / Timeout / DriverNotSupported / Unknown

### 4.4 新增数据库驱动的对接方式

后端采用 trait 驱动的多数据库抽象。新增一种数据库只需：

1. 在 `src-tauri/src/database/` 新建驱动文件，实现 `DatabaseDriver` trait（`database/mod.rs`），约 24 个方法：`query` / `execute` / `cancel_query`、`get_databases/tables/columns/indexes/foreign_keys`、`get_views/triggers/procedures/functions` 及定义读取、`get_users`、`execute_batch`、`export_table_csv`、`dump_table`、`escape_identifier` 等。
2. 在 `create_and_connect_driver()` 工厂中注册新 `driver_type`。
3. 前端 `lib/ddl.ts` 增加对应方言的 DDL 生成（建库 / 建表 / ALTER）。
4. i18n 字典（`src/i18n/zh-CN.ts` / `en-US.ts`）补充相关文案。

### 4.5 安全边界

- 密码仅存在于后端内存与加密落盘文件中（AES-256-GCM），任何 IPC 返回不携带密码。
- 连接配置存放于用户配置目录（`app_config_dir`），安装版与便携版互不冲突。
- 日志存放于 `app_log_dir`，滚动切割。
