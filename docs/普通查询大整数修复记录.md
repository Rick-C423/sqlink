# 普通 SQL 结果大整数精度修复

日期：2026-10-20。范围为本地未提交工作区；保留原有改动，未提交、推送、发布或替换现用 EXE。

## 行为与边界

普通 SQL 返回的标量整数现在与受控表显示遵守同一规则：`-9007199254740991` 至 `9007199254740991` 保留 JSON Number；超出范围的 int64/uint64 在传输时输出规范十进制字符串。例如 `9007199254740993`、`-9223372036854775808`、`18446744073709551615` 不再先被 JavaScript 舍入。前端显示和复制不将其转回 Number。

保护集中在 `RowData.values` 的序列化边界。四个驱动保留原生整数 JSON 值，SQL 转储和 CSV 继续使用这些原值；没有把所有数字字符串当作整数，也没有改变 SQL 转储的字面量类型。受控结果 `TypedValue::display_json` 复用同一整数显示规则，后端真实键、行快照、参数绑定与授权不变。MCP 查询序列化同样经过该边界。

本地排序对有明确整数类型的列使用 BigInt 比较，兼容安全范围 Number 与超范围字符串、正负整数及 NULL。数字 TEXT 和类型未知的表达式仍沿用字符串比较，不从内容猜测数据库类型；分页排序仍由原服务端回调处理。SQLite 无声明类型的表达式能无损显示，但不会凭显示值推断整数排序。

普通 SQL 和筛选结果继续只读，不授予 `resultContext`、行句柄或编辑能力，也不扩大现有受控网格的数据库版本和类型范围。本次仅处理结果行内的标量整数；嵌套 JSON、浮点数自身精度和行外计数字段不在本次变更范围。
